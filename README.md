## Project Overview

Bhumi Survey 3D is an open-source 3D property intelligence platform for India, providing:
- Interactive 3D city exploration
- AI-powered building detection from drone/satellite photos
- ULPIN property ID generation and validation
- Floor/flat-level details and ownership status
- Underground infrastructure awareness (pipes, cables)
- User authentication and property management

---

## Architecture

```
Frontend (Vercel) → Backend (Render) → PostgreSQL Database
```

- **Frontend**: React + TypeScript + Tailwind CSS + Three.js
- **Backend**: FastAPI (Python) with CORS, JWT authentication
- **Database**: PostgreSQL 15 (Render managed)

## Quick Start

### Prerequisites

- Python 3.12+
- Node.js 18+
- Git
- Docker (optional, for local development)

### Local Development

#### 1. Backend

```bash
cd backend
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env  # Edit with your values
python -m app.main  # Runs on http://localhost:8000
```

#### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env.local  # Set VITE_API_URL
npm run dev  # Runs on http://localhost:5173
```

#### 3. Full Stack (Docker)

```bash
docker compose up --build
```

## Deployment

### Vercel (Frontend)

1. Create new repo on GitHub: `bhumi-survey-3d`
2. Import this repo to Vercel
3. Set environment variable: `VITE_API_URL=https://bhumi-survey-3d-api.onrender.com`
4. Deploy

### Render (Backend)

1. Create new Web Service on Render
2. Connect GitHub repo: `bhumi-survey-3d`
3. Build Dockerfile from `backend/`
4. Add PostgreSQL database add-on
5. Set environment variables:
   - `DATABASE_URL` (auto-generated by Render)
   - `JWT_SECRET=<random-64-chars>`
   - `CORS_ORIGINS=https://bhumi-survey-3d.vercel.app`
6. Deploy

## API Authentication Flow

```
User visits /login or /signup
       │
       ├── POST /api/auth/signup → Backend
       │     → bcrypt hash → User row → JWT token → stored in AuthContext
       │
       ├── POST /api/auth/login → Backend
       │     → verify password hash → JWT token → stored in AuthContext
       │
       ├── Every subsequent request:
       │     Authorization: Bearer <JWT-token>
       │
       ├── CORS check on Backend:
       │     Origin matches → allowed
       │     Otherwise → 403 Forbidden
       │
       └── Protected pages check AuthGuard → redirect to Login if no token
```

---

## Authentication System

| Feature | Details |
|---------|---------|
| **Signup** | `POST /api/auth/signup` — username, email, password → bcrypt hash |
| **Login** | `POST /api/auth/login` — email + password → verify hash → JWT (24h) |
| **Logout** | `POST /api/auth/logout` — clear client-side token |
| **Token Storage** | `httpOnly` cookie (preferred) or `localStorage` |
| **Protected Pages** | Dashboard, Map3D, Analysis, ULPIN, Validation, Infrastructure |
| **Public Pages** | Landing, Login, Signup |
| **Password Storage** | Never plain text — always bcrypt hash |
| **User Model** | `id, username, email, password_hash, created_at` |

## Development

### Adding New Features

1. **Backend**: Add route in `app/routes/`, service function, update models if needed
2. **Frontend**: Add page component, add route in `App.tsx`, update AuthGuard if needed
3. **API**: Update `frontend/src/api/client.ts` if new endpoints
4. **Deploy**: Push to GitHub → Vercel/Render auto-deploy

### Code Conventions

- **Python**: Black formatter, isort imports, type hints
- **TypeScript**: Strict mode, interface for all props, ESLint
- **CSS**: Tailwind utility-first, mobile-first responsive
- **Commits**: Conventional commits format
- **Branching**: `main` branch production, feature branches for new work
